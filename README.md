# LIME FIT 0.7 — восстановление web-сборки

Исходный каталог `/workspace/lime-fit` и его локальный архив не восстановились в новой среде. Здесь сохранено воспроизводимое обновление опубликованной web-сборки 0.4. Это НЕ исходный проект Expo/TypeScript: нативная сборка из этого каталога не поддерживается.

База: GitHub commit `5ac33fb5edd5c0fe6280d880a07c4cb124ed3464`, архив `original-web.zip`, SHA-256 `d04c8254ca3285d86c6a80f1bdc0932a021c7bd19569d8e435691d7e0799a6fe`. Перед извлечением проверяется точная контрольная сумма. `recover.cjs` извлекает определения модулей Metro; `build.cjs` заменяет только перечисленные модули приложения с проверкой однократного совпадения. Зависимости платформы не переписываются. Результат получает новое имя JS-бандла по SHA-256.

## Воспроизведение

Требуются Node.js 22+ (проверено на текущем Node), npm, Python 3. Для браузерных тестов нужен Chromium `/usr/bin/chromium`.

```sh
npm ci --cache /workspace/.npm-cache
npm run build
npm test
npm run test:e2e
npm start
```

Сервер разработки слушает 127.0.0.1:4173; этот адрес недоступен на телефоне из другой сети. Для пользовательского доступа и ИИ подключите Git-сборку существующего Netlify-сайта по инструкции [AI-SETUP](docs/AI-SETUP.md). Статическая загрузка `dist` не разворачивает функции ИИ. Expo Go для этой версии не нужен.

## Изменения

- Среда: грудь и руки, 22 рабочих подхода с прессом. Пятница: спина и плечи, 20. Воскресенье: ноги и пресс, 29. Пресс в начале.
- В воскресном плане цели отдельных подходов повторяют предоставленные пользователем веса и повторения прошлого занятия. Это черновик следующей тренировки, не история. Старый RIR не задаётся как цель. Сгибание ног сидя и внешние веса других дней остаются пустыми.
- Болгарский присед: 10 кг на гантель = 20 кг суммарно. Икры — стоя в Смите, отдельный идентификатор от варианта сидя. По умолчанию выбраны верхний блок и EZ-гриф на скамье Скотта; альтернативы можно выбрать в редакторе.
- `PlanExercise.targets` хранит `{weight, weightKg?, reps}` по подходам. Начатое занятие хранит неизменяемые `targetWeight`/`targetReps` и отдельные редактируемые фактические поля. Факт учитывается только после подтверждения.
- Редактор позволяет менять каждую цель. Изменение общего веса или повторений убирает индивидуальные цели; изменение числа подходов обрезает/дополняет их. Новый подход в занятии остаётся без результата.
- Цели конвертируются между кг/фунтами через канонический вес без накопления округлений. Новая копия имеет формат 4; поддерживается чтение форматов 1–3. Не импортируйте новые копии в старое приложение.
- Применение требует действия пользователя, сохраняет профиль, историю и активное занятие, поддерживает отмену до изменения применённого плана. Никаких записей прошлого занятия автоматически не создаётся.

`src/program.json` и `src/exercises.json` — редактируемые данные; `src/install-targets.js` — логика целей; `build.cjs` — точечные преобразования восстановленных модулей и UI. `original-web.zip` и эти файлы достаточны для восстановления. `original-modules`, `updated-modules`, `original-bundle.js` и `dist` генерируются.

## ИИ-тренер и навигация

Убрана отдельная вкладка библиотеки; старый адрес перенаправляет в программу. Данные упражнений для программы и истории сохранены. Новый чат использует серверные Netlify Functions и Groq API. Ключ не попадает в web-сборку. Вход по отдельному паролю, подписанная HttpOnly-сессия, проверка Origin, ограничение запросов, согласие на передачу сокращённого контекста. Ответы не изменяют записи автоматически.

Подключение: [пошаговая инструкция](docs/AI-SETUP.md). Без серверного ключа и развёрнутых функций реальный ИИ не подключён. Бесплатная квота зависит от провайдера и региона.

Проверено: 13 тестов данных/серверного протокола и 5 браузерных сценариев. Вызовы модели заменены фикстурами; реальный Groq и Netlify Functions в облаке не проверены. Это проверки восстановленной web-версии, не исходного TypeScript или нативного SQLite.
